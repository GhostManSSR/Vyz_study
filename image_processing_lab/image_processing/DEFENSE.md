# Шпаргалка для защиты лабораторной

## Кратко о работе

«На основе готового класса `Image` я реализовал параллельную пакетную обработку
изображений. Программа рекурсивно ищет файлы, кладёт задания в общую очередь,
создаёт заданное количество рабочих потоков. Каждый поток извлекает один файл,
загружает его, применяет фильтр и сохраняет PNG. Общая очередь защищена мьютексом,
результаты считаются атомарными счётчиками, а время измеряется через `chrono`.»

## Что открыть в коде

| Место (`src/main.cpp`) | Объяснение |
| --- | --- |
| `Options`, `parseArgs()` | Чтение каталогов, фильтра и числа потоков из командной строки |
| `Task` | Одна задача: путь исходного и выходного файла |
| `collectTasks()` | Обход каталогов `std::filesystem`, заполнение очереди |
| `ImageProcessor::run()` | Запуск `std::thread` и ожидание `join()` |
| `ImageProcessor::workerLoop()` | Извлечение задачи, вызовы `Image::load`, `grayscale`/`invert`, `Image::save` |
| `std::lock_guard<std::mutex> lock(queueMutex_)` | Критическая секция для общей очереди; только один поток берёт очередное задание |
| `std::lock_guard<std::mutex> lock(logMutex_)` | Сообщения из разных потоков не перемешиваются |
| `std::atomic` | Потокобезопасный подсчёт успехов и ошибок |
| `std::chrono::steady_clock` | Измерение длительности обработки |

## Самые вероятные вопросы

**Что такое поток?** Независимая последовательность выполнения внутри процесса.
Рабочие потоки могут выполняться параллельно на нескольких ядрах CPU.

**Зачем `std::queue`?** Все рабочие потоки получают задачи из одной общей очереди.
Очередь обеспечивает динамическое распределение: быстрый поток сможет взять
больше файлов и не ждать медленный.

**Почему нужен `mutex`?** Операции `empty`, `front`, `pop` с общей очередью
нельзя одновременно выполнять из разных потоков. Без синхронизации будет гонка
данных и возможно повторное извлечение или потеря заданий.

**Почему `lock_guard`?** Это RAII-обёртка: мьютекс блокируется при создании
`lock_guard` и освобождается автоматически при выходе из области видимости.

**Почему мьютекс стоит только вокруг извлечения задачи?** Если держать его
во время обработки изображения, потоки будут работать по очереди, и реального
параллелизма не получится.

**Почему не нужен мьютекс для `Image::grayscale()`?** Каждый рабочий поток
создаёт собственную локальную переменную `Image image`, поэтому его пиксели
не разделяются с другими потоками.

**Что такое `atomic`?** Тип для безопасных одновременных операций над одним
значением из разных потоков. Используем для числа успешно обработанных файлов
и числа ошибок.

**Зачем `join()`?** Чтобы главный поток дождался окончания всех рабочих потоков
и не завершился раньше, чем будут сохранены изображения.

**Чем `std::vector<std::thread>` отличается от `std::queue<Task>`?** Вектор
хранит объекты запущенных потоков, а очередь — задания, которые ещё предстоит
выполнить.

**Почему 4 потока могут быть медленнее 1?** Из-за создания потоков, конкуренции
за диск, малого количества файлов, кэшей процессора и других накладных расходов.

**Что произойдёт с испорченным PNG?** `Image::load()` вернёт `false`;
рабочий поток зарегистрирует ошибку, продолжит оставшиеся задачи; итоговый
код завершения программы будет 1, если были ошибки.

**Что делает `grayscale`?** Вычисляет яркость пикселя по взвешенной сумме каналов
RGB (`0.299R + 0.587G + 0.114B`) и записывает результат в три RGB-канала.

**Что делает `invert`?** Заменяет каждый RGB-канал на `255 - значение`, альфа
сохраняется.

## Показ программы преподавателю

1. `./build/image_processor examples/input examples/result_1 grayscale 1`
2. `./build/image_processor examples/input examples/result_4 grayscale 4`
3. Открой результаты `examples/result_1/` и `examples/result_4/`, сравни.
4. `./build/image_processor examples/input examples/result_invert invert 4`
5. `ctest --test-dir build --output-on-failure` — покажи успешные тесты.
6. Для оценки скорости создай крупные входные данные через скрипт из README.

**Честная оговорка:** полного текста задания нет в исходном ZIP. Если преподаватель
требует специальную модель producer-consumer с `condition_variable` или другую
схему параметров, такую часть нужно адаптировать отдельно.
