# Лабораторная работа №13 — протокол «слепой» подписи

## Требования
- .NET 10 SDK
- C# / `BigInteger`
- RSA с двумя 1024-битными простыми числами `p`, `q`
- `n = p*q` примерно 2048 бит
- `e = 65537`
- `d = e^-1 mod phi(n)`
- SHA3-256

## Запуск

```bash
dotnet run -c Release
```

## Структура

- `Program.cs` — демонстрация протокола и консольный интерфейс.
- `Client/VotingClient.cs` — логика клиента: бюллетень, хэширование, ослепление, снятие ослепления.
- `Server/VotingServer.cs` — логика сервера: выдача слепой подписи, контроль одной выдачи, проверка подписи и открытая база.
- `Crypto/RsaBlindSignature.cs` — RSA, генерация ключей, модульное обращение, генерация взаимно простого `r`.
- `Crypto/BallotHash.cs` — SHA3-256.
- `Models/Ballot.cs` — модель бюллетеня и варианты ответа.

## Формулы

Пусть `B` — бюллетень, `H = SHA3-256(B)`.

Клиент выбирает случайное `r`, такое что `gcd(r,n)=1`.

Ослепление:

`B' = H * r^e mod n`

Сервер подписывает:

`S' = (B')^d mod n`

Клиент снимает ослепление:

`S = S' * r^-1 mod n`

Проверка:

`S^e mod n == H`

## Почему сервер не видит голос при выдаче подписи

Во время первого этапа сервер получает только `B'`. Благодаря случайному множителю `r^e` сервер не может восстановить `H` из `B'`, не зная `r`.

После получения подписи клиент снимает ослепление и отправляет `B` и `S` через условно анонимный канал. В учебной реализации канал моделируется вызовом метода, потому что задание прямо разрешает не реализовывать сетевую часть.

## Ограничения учебной реализации

Это демонстрация криптографического протокола, а не готовая система электронного голосования. Для реальной системы нужны транспортная безопасность, аутентификация, защита от Sybil-атак, полноценное управление идентичностью, журналирование, распределённое хранение и продуманный механизм анонимного канала.
