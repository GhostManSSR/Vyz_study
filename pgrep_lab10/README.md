## Сборка

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

**Linux / macOS**, бинарник: `./build/pgrep`.

**Windows** (Visual Studio / CMake): `build\Release\pgrep.exe` (или другой путь, указанный CMake).

Без CMake (Linux):

```bash
g++ -std=c++17 -O2 -Wall -Wextra -pthread main.cpp -o pgrep
```

## Запуск

```text
pgrep [OPTIONS] PATTERN [PATH...]
```

`PATTERN` — обязательная буквальная подстрока, в том числе пустая `""`; `PATH...` — файлы/каталоги. Если не передать `PATH`, используется текущий каталог (`.`). Для обработки каталогов требуется `-r`.

| Опция | Действие |
|---|---|
| `-r` | Рекурсивно искать в каталоге, не следуя символическим ссылкам |
| `-i` | Игнорировать регистр латинских букв ASCII |
| `-v` | Выводить строки, **не** удовлетворяющие поиску |
| `-n` | Печатать номер строки с единицы |
| `-H` / `-h` | Всегда / никогда не печатать путь перед строкой |
| `-c` | Печатать количество выбранных строк по каждому файлу, включая нули |
| `-l` | Печатать только имена файлов с хотя бы одной выбранной строкой |
| `-j N` | Число потоков, `N >= 1`; `-j 1` — настоящий последовательный режим |
| `-w` | Только целое слово: границы определяются по `[A-Za-z0-9_]` |
| `-x` | Полное совпадение с содержимым строки |
| `-q` | Без вывода в stdout и stderr, результат только в коде завершения |
| `--` | Завершить список опций: `pgrep -- -foo file.txt` |

Поддерживаются группы опций: `-rni`, `-vc`, `-j4`, `-rnj 4`. Если указаны `-H` и `-h`, действует последняя из них. При `-l` печатаются пути, при `-c` — счётчики, при `-q` не печатается ничего.

### Примеры

```bash
./build/pgrep -n foo examples/a.txt
./build/pgrep -rni -j 4 foo examples/
./build/pgrep -rc TODO examples/
./build/pgrep -rl cat examples/
./build/pgrep -w cat examples/a.txt
./build/pgrep -x foo examples/a.txt
./build/pgrep -q error examples/a.txt && echo found
```

Строковый вывод: `[путь:][номер:]содержимое`. Путь при обычном выводе виден, когда входных путей больше одного, задан `-r` или `-H` (кроме `-h`). Для `-c` по умолчанию печатается `путь:число` даже для одного файла, как в примерах задания; `-h` убирает путь. Для `-l` всегда печатается имя файла. Порядок вывода при многопоточности **не гарантирован**, но строки одного файла выводятся вместе.

Сводка отправляется в `stderr`:

```text
Processed: 2 files, 3 matches, 0 errors, 0.001 s
```

`matches` — число **выбранных строк**, а не количество вхождений шаблона внутри строки. Инверсия `-v` применяется до `-c` и `-l`. В этой реализации `success + errors = total`, где `total` включает успешно обработанные файлы и отдельные неудачные попытки открытия/обхода.

Коды завершения: `0` — есть выбранные строки, `1` — нет, `2` — есть ошибки; в режиме `-q` совпадение даёт `0` даже при ошибке в другом файле.

## Архитектура

1. Главный поток разбирает аргументы и собирает список регулярных файлов через `std::filesystem`. Каталоги без `-r` считаются ошибками, симлинки не разыменовываются.
2. Если `-j 1`, главный поток обрабатывает каждый файл сам, **без создания потоков**.
3. Иначе главный поток помещает пути в `std::queue<fs::path>` и запускает рабочие `std::thread` (не больше количества файлов). Рабочие берут следующий путь под короткой блокировкой `queue_mutex` и сразу освобождают мьютекс.
4. Вся работа с открытием и построчным чтением выполняется **вне мьютекса очереди**. Каждый файл обрабатывается только одним потоком.
5. Вывод готовится внутри обработки конкретного файла и выдаётся под `output_mutex`: строки разных потоков не перемешиваются. Счётчики результатов — `std::atomic`.
6. Главный поток выполняет `join()` для всех рабочих и печатает статистику.

**Обработка ошибок.** Ошибка чтения/открытия не прерывает работу с остальными файлами. Текстовые файлы читаются побайтово (`std::ios::binary`) и построчно, включая последнюю строку без `\n`. Встроенный байт NUL считается признаком бинарного/повреждённого файла: он регистрируется как ошибка, результаты такого файла не публикуются. Совпадение по регистру специально ограничено ASCII; произвольные UTF-8 символы могут искаться буквально, но не приводятся к нижнему регистру.

**Ограничение.** Для целостного вывода и отказа от частичных результатов файл сначала накапливает выбранные строки в памяти. Для очень больших файлов со множеством совпадений потребление памяти может быть заметным. Это сознательный компромисс ради простой и безопасной обработки ошибок в учебной работе.

## Проверка

Для автоматических тестов нужны Python 3 и `g++`:

```bash
python3 -m unittest discover -s tests -v
```

Проверяются фиксированный поиск, регистр, инверсия, `-w/-x`, пустые шаблоны/файлы, вывод/номера, `-c/-l/-q`, несуществующие и бинарные файлы, симлинки, рекурсивный обход и сравнение `-j 1` с `-j 4` на 40 файлах.
