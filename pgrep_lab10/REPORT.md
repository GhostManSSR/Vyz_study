# Отчёт по практической работе №10

**Тема:** «Параллельный grep».  
**Язык:** C++17.  
**Цель:** реализовать консольный поиск фиксированной подстроки в текстовых файлах с последовательной и многопоточной обработкой.

## 1. Выполненные требования

Реализованы разбор командной строки `pgrep [OPTIONS] PATTERN [PATH...]`, поиск фиксированной подстроки, рекурсивный обход файлов через `std::filesystem`, два способа обработки (`-j 1` и `-j N`), опции `-r`, `-i`, `-v`, `-n`, `-H`, `-h`, `-c`, `-l`, `-j`, `-w`, `-x`, `-q`, `--`. Реализованы вывод ошибок в `stderr`, итоговая статистика и коды завершения 0/1/2.

## 2. Алгоритм

1. Главный поток читает параметры программы и создаёт список путей к файлам.
2. В последовательном режиме главный поток открывает файлы по одному.
3. В параллельном режиме пути помещаются в общую очередь `std::queue<fs::path>`. Рабочие `std::thread` берут очередной путь под защитой `std::mutex`. Считывание файла и поиск выполняются вне критической секции.
4. Каждый файл полностью обрабатывается одним потоком. Отобранные строки файла выдаются через общий мьютекс вывода, а общие счётчики обновляются атомарно.
5. После окончания всех задач главный поток делает `join()` и выводит число файлов, совпадений, ошибок и время.

Такой подход снижает длительность критических секций, предотвращает гонки между обработчиками и не требует разбиения одного файла на части. Порядок файлов при параллельной обработке может отличаться от исходного; это допустимо по условию.

## 3. Особые случаи

- Пустой шаблон совпадает со всеми строками; `-x ""` — только с пустыми строками.
- Инверсия `-v` применяется после поиска, до подсчёта `-c` и отбора файлов `-l`.
- Последняя строка без `\n` обрабатывается.
- Пустой файл выдаёт 0 совпадений.
- Не существующие, недоступные и содержащие NUL файлы учитываются как ошибки; остальные файлы продолжают обрабатываться.
- Символические ссылки не разыменовываются.
- Инвариант: **успешных обработок + ошибок = всего попыток**.

## 4. Проверка программы

Для тестирования выполнена компиляция `g++ 14.2.0` с флагами `-std=c++17 -O2 -Wall -Wextra -pthread`. Проверка производится командой:

```bash
python3 -m unittest discover -s tests -v
```

**Результат:** 16 тестов из 16 успешно прошли. Тестировались параметры поиска, формат вывода, пустые файлы и строки, ошибки чтения, отсутствие следования по симлинкам и эквивалентность режимов на 40 текстовых файлах (80 совпавших строк).

Пример тестового запуска:

```bash
./build/pgrep -rni -j 4 foo examples/
```

На двух демонстрационных файлах обнаружены 3 подходящие строки, ошибок нет. Порядок строк между файлами не фиксирован. Сравнение производительности для конкретной машины можно выполнить, повторив запуск с `-j 1` и `-j 4` на большом наборе файлов: выигрыш зависит от скорости накопителя, объёма данных и количества доступных ядер, поэтому фиксированное ускорение не гарантируется.

## 5. Вывод

Разработана утилита поиска текста, которая использует многопоточность на уровне независимых файлов. Общая очередь обеспечивает динамическое распределение файлов между рабочими потоками, а мьютексы защищают операции над общей очередью и выводом. Программа учитывает ошибки отдельных файлов и сохраняет работоспособность при обработке остальных данных.
