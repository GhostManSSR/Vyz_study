# Лабораторная работа №2: минимизация конечного автомата

Требуются JDK 21, Gradle Wrapper (включён в проект), Graphviz и POSIX GNU Make / shell для изображений.

Из каталога `NKAminimizationDKA`:

```sh
./gradlew build
./gradlew run --console=plain
make img
```

На Windows для Gradle используйте `gradlew.bat`; задайте `JAVA_HOME` на JDK 21.
Для Makefile подойдут MSYS2 GNU Make и POSIX shell. Нативная Windows-сборка Make
в сочетании с Git Bash может искажать русские имена файлов; используйте POSIX-сборку.
Команда Gradle `run` работает в каталоге `app`, поэтому DOT и PNG находятся в `app/graphs`.
При прямом запуске Java графы записываются в `graphs` относительно рабочего каталога.
`make clean` удаляет только три известных PNG, сохраняя DOT и посторонние файлы.

## Преобразования

Детерминизация строит только достижимые непустые подмножества BFS в порядке обнаружения.
Пустое множество означает отсутствующий переход; отдельное состояние для него здесь не создаётся.
Вывод содержит таблицу подмножеств, их новые обозначения и итоговый ДКА.

Минимизация удаляет недостижимые состояния и дополняет отсутствующие переходы
поглощающим отвергающим состоянием с уникальным именем. Затем уточняет разбиение
до стабильных классов эквивалентности. Результат минимален среди **полных ДКА**:
класс ошибки сохраняется, если он различим с остальными классами. Частичный ДКА
при соглашении об удалении класса ошибки может иметь на одно состояние меньше.
Эквивалентные отвергающие состояния объединяются с классом ошибки, в том числе
для пустого языка: результат имеет ровно одно состояние.

Исходные автоматы не изменяются. Конструктор проверяет исходную таблицу до её
нормализации и копирует вложенные коллекции; доступ наружу предоставляется только для чтения.
Автоматы не поддерживают ε-переходы. В консольном вводе состояния и символы разделены запятыми,
`-` обозначает пустое множество. Некорректные данные отклоняются через `IllegalArgumentException`.

## Проверки

JUnit 5 проверяет точные таблицы лекционного НКА и трёхсостоянийного ДКА,
гомоморфизм шестисостоянийного примера на классы `{q0,q2}`, `{q1,q3}`, `{q4,q5}`,
а также принятие всех двоичных строк длиной 0–8 независимым интерпретатором НКА.
Ожидаемые языки проверяются непосредственно через `endsWith("11")` и `contains("00")`.
Перебор конечного набора слов дополняет структурные проверки, но не заменяет доказательство.

Регрессионные проверки покрывают неполные переходы и класс ошибки, недостижимые и
неэквивалентные состояния, несколько заключительных состояний, пустую строку,
достижимость подмножеств на 40 исходных состояниях, неверные таблицы и null,
защиту коллекций, неизменность входов, DOT-экранирование и оба режима консольного приложения.
Консольные тесты запускаются в отдельных временных каталогах и не перезаписывают графы проекта.

Результаты JUnit: `app/build/reports/tests/test/index.html`.
